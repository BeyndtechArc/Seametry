Every number below is decoded from mint account bytes by `internal/registry`,
never read from an issuer's published list. A published list is evidence of
intent at the time it was written. The account is what is true now.

This note is generated by the same run that produced the data, so the two
cannot disagree.

The transfer hook row is the one worth sitting with. Not a single mint has an
active hook, so a product reporting hooks as a boolean would report none at
all and be wrong about every one of the 1124. The hook exists on each of them,
switched off, with a named authority who can switch it on at any moment and
without any other change to the mint. Reporting that as absent is not a
simplification, it is a different fact.

## The multiplier field

| | Mints |
|---|---|
| Carrying Scaled UI Amount | 1124 |
| **Where the field named `multiplier` is stale** | **383 (34.1%)** |
| Activation scheduled but not yet effective | 5 |

Scaled UI Amount carries `multiplier`, `new_multiplier`, and
`new_multiplier_effective_timestamp`. The live value is `new_multiplier` once
its timestamp has passed, otherwise `multiplier`. Anything reading the obvious
field is one corporate action behind on a third of this market.

### It is not a rounding error

| Symbol | The obvious field says | The live value is | Effective since |
|---|---|---|---|
| NFLXx | 1 | **10** | 2025-11-16 |
| PPLTx | 1 | **10** | 2026-05-17 |
| PALLx | 1 | **5** | 2026-05-17 |
| CRWDx | 1 | **4** | 2026-07-02 |

Splits, where the obvious field never moved from its initial value. Anyone
pricing a position in NFLXx from that field values it at a fraction of what it
is.

The rest are smaller and more insidious: one corporate action behind rather
than many, often under a tenth of a percent. That is still a real mispricing
on every share, and a system catching only the dramatic cases would pass the
splits above and fail silently on the others.

### The opposite error

5 mints had an activation scheduled but not yet
effective at capture. Returning `new_multiplier` before its timestamp is
exactly as wrong as returning the stale field after it, and only a mint in
this state can catch that. One is kept in the fixture set for that reason,
resolved against a fixed reference time so the case survives the activation
landing.

## Decoder coverage

| Mints decoded | 1124 of 1124 |

The last row is reported because it is the one that will change. When an
issuer adopts an extension Seametry has not implemented, it appears here by
number rather than being dropped, and it reaches the interface as a sentence
saying there is a control we do not yet decode. An unknown that is silently
discarded is indistinguishable from an absent one at every layer above, which
is how a new issuer power becomes invisible.

## What this does not establish

- **Only one issuer.** xStocks mints only. Backpack Securities is not covered,
  and its dividend mechanism, a multiplier change or newly minted tokens,
  remains an open question that a fixture capture will settle.
- **A moment, not a trend.** One slot. The share moves as issuers update
  fields, and the large splits will eventually be cleaned up.
- **Nothing about intent.** An issuer holding a power is not an issuer misusing
  one. Every issuer holding a given power gets the identical sentence here.
- **Nothing about depth.** Whether any of these can actually be traded at size
  is a separate measurement and a separate ceiling.
